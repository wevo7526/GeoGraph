# Platform audit — 2026-08-15

Against the brief: a Relationships page much richer in insight; a Game-Theory
page per region mapping future events as scenarios from solved games (BNE, LP,
ML); a per-dyad solved game with forecasts, explanation and charts; a Markets
page with the paper-money backtest per region; a white design system with a
black-bordered white knowledge-graph plate; every store persisted, registered
and consumed by ML / LP / games; market movement traced for every dyad across
the three packs. Live state checked at https://geograph.up.railway.app (graph
open, 817,155 Events, 632,586 AFFECTED, 18 Forecast nodes, 3 packs).

## Findings (file:line = where the fact lives)

### Frontend
- Four tabs (`web/src/components/TopBar.tsx:52-57`); `/games`, `/reasoning`,
  `/trading` are aliased INTO the Relationship page (`App.tsx:86-95`) — the
  Games/Trading pages were deleted in `6ee5f2d`. `GameViz.tsx` is orphaned.
- No chart library; `charts/Charts.tsx` holds `LineBand` (used), `Strip`,
  `Fan`, `BoxRow` (unused — built for `/api/precedent`, which nothing calls).
- Relationship page reads one line of the game (`paths[0].steps[0]`), only
  the near-term forecast, a region-wide track record, and a timeline whose
  entries have no title (`core/reasoning/impact.py:212-215` emits
  `{event_id,date,markets}` only). `/api/impact/{event_id}` (measured vs
  expected vs surprise) is never called by the web.
- Backtest ledger rows are fetched and discarded (summary only). No equity
  curve, drawdown, positions or standing-book view anywhere.
- Design system is fully token-driven (`styles.css:26-46`); the only
  hardcoded colours are Graph3D's WebGL constants (duplicated by design).

### Games / LP / ML
- Solver: quantal-response MPBE by backward induction (`core/games/solve.py`).
  **No LP anywhere in the repo** (no linprog/cvxpy/pulp/simplex); the stage
  game is solved by logit sweeps. Belief is NOT a policy axis
  (`solve.py:184`); `state.State/all_states/belief_grid` are dead.
- `/api/games/explore` is per dyad and persists nothing (`frozen: false`).
  The frozen `sequence` Forecast covers 6 dyads per region and is written
  only on an opt-in measuring boot; `scenarios_json="[]"` so it can never be
  scored (`calibration.score_forecast` refuses).
- No region-level scenario object, no scenario naming, no explanation text,
  no value-function output, no per-step beliefs in any payload.
- ML: ridge on `deviation`, shipped features are TWO (`intercept`,
  `level_now`, `features.py:72` — CLAUDE.md says three; the artifact settles
  it). Gate passes. Consumed only through the frozen `model` Forecast → the
  ML→game tilt (`bridge.py`).
- Every fitted game sits at a parameter bound (`models/game-*.json`
  `at_bounds`); mena and china `converged: false`.

### Persistence / registration
- Market effects surface is graph-only (`effects.effects_for_dyad`,
  `pricing.measured_effects`, `impact.py`); `pricing.measured_effects:47`
  filters `region_pack = $pack`, dropping every COW MID (`region_pack=""`).
- `games.py:116-119` sets `effects = {}` when the graph is closed; consumers
  iterate a list.
- `run_event_study._effect_source` maps only DGS2/DGS10 to FRED — DGS3MO
  effects carry `source:yfinance` (provenance mislabel). FRED yields need
  `FRED_API_KEY`; unset ⇒ three markets silently empty in every pack.
- `/api/dyads?region=` ignores the region (32 identical rows per region).
- Persisted but unserved: `market_intraday`, `event_study_runs` skips, PG
  `wire_*` tables (no boot step, no reader). Consumed by nothing in ML /
  games / forecasts: `NetworkMetric`, `RELATES_TO`, `FLOW`, `Issue`. Dead:
  `sensor_loop.update_from_effect` (tests only), `analogy.find_analogues`,
  `ingestion/{gpr,acled,ucdp,icb,jst}.py` (raise NotImplementedError).
- Backtest persisted for **mena only** in production (76 quarters); china
  and eurasia return "no persisted backtest".

## What this session builds (architecture)

1. `core/games/equilibrium.py` — an LP stage solver: the welfare-maximal
   correlated equilibrium of each stage game by `scipy.optimize.linprog`
   (HiGHS), with the distance of that CE from a product-form (Nash) solution
   reported as `nash_gap` — how far the LP solution stands from the BNE. The
   backward-induction recursion runs on either concept (`solver="lp"|"qre"`).
2. `core/games/scenarios.py` — a region scenario map: every active dyad in
   the region solved (LP and QRE), tilted by the ML model where it applies,
   paths priced to markets, action courses named as scenarios with
   likelihoods, aggregated to a region future-event map; a deterministic
   explanation writer that narrates from the numbers only.
3. Persistence: PG `game_solutions` (region, dyad, as_of, payload) written by
   `scripts/solve_games.py`; served by `/api/games/region` and
   `/api/games/dyad` from the store with a live fallback flagged `persisted:
   false`. Backtests run and persisted for all three regions.
4. Registration fixes: `/api/dyads` region filter; `games.py` effects list;
   `pricing` keeps deep-tier effects; DGS3MO → FRED provenance; timeline rows
   carry name / goldstein / first mover; `/api/impact/coverage` registers
   measured-vs-total events per dyad per pack so the market-movement trace is
   auditable for every dyad.
5. Frontend: white design system (done); Explorer plate white with a black
   border (done); `/relationships` richer (precedent fan + market boxes,
   named timeline with expected/measured/surprise, four forecast modes, the
   full game read); `/games` (region map + dyad drill-in with charts and
   explanation); `/markets` (per-region equity curve, drawdown, ledger,
   positions, standing book). Charts stay hand-rolled SVG on the tokens.
